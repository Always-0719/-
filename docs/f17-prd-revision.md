# 父 PRD 修订建议：F17 微信订阅消息（B 线提请，待三线会签）

日期：2026-11-21 · 依据：docs/r3-wechat-report.md（R3 文档级验证）+ 步骤 16 落地情况

## 现状
- R3 结论：**条件可行**。一次性订阅消息链路成立（个人主体可用），但额度收集强依赖小程序载体——`wx.requestSubscribeMessage` 为小程序专属 API，H5 无法调起。
- 项目已确认 H5 先行；截至步骤 16 无小程序 AppID、无模板 tmplId、无原生壳页面（R3 缺口清单全空）。

## 建议修订
1. F17 验收「有额度时微信触达」改为**条件验收**：小程序壳 + AppID + 模板就绪后真机验证一条订阅消息；此前以「额度账本 + 降级链完整 + 单测覆盖」为 MVP 交付口径。
2. MVP 第 2–5 周真实通道为站内 + 邮件；`WECHAT_ENABLED=false` 默认关闭，额度收集端点与账本已建（步骤 16），小程序壳就绪后开 flag 即可接真。
3. subscribe_quota 记账粒度：PRD 按 user 记 remaining；接真时细化为按 (user, template) 记账（MVP 单模板场景两者等价）。
4. 长期订阅不可替代（仅线下公共服务类目开放，个人主体无资格）——父 PRD 如有长期订阅表述应删除。

## 不受影响
- 提醒永不丢：任何微信失败/无额度路径回落邮件 + 站内（wechat.test.js 锁定）。
- 冻结 8 端点、TaskDraft v1、Event v1 均不变；collect/quota 为 B 自主新增端点。
